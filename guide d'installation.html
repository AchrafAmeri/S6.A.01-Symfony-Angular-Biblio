Étape 1 : Environnement de Développement

À cette étape, nous allons valider l'installation des outils de développement, initialiser le projet et notre espace de travail.

⚠️ Ce guide est rédigé pour Windows, qui est l'environnement des PC de l'IUT. La version portable de MariaDB fournie sur Moodle est également une version Windows.
Si vous travaillez sous Linux ou macOS, vous devrez installer par vos propres moyens PHP 8.4, Symfony CLI 5.16, Node.js 22, VSCode et un serveur MariaDB (ou MySQL) avec des versions compatibles. Les étapes du POC resteront les mêmes.

Attention : avec les logiciels que nous listons ci-après, nous allons naturellement créer des projets Symfony 7.4 et Angular 21. Si vous installez des versions plus récentes, vous pourrez très probablement suivre les étapes du POC (Proof Of Concept), mais quand vous commencerez le projet, nous vous conseillons très fortement de vérifier dès le début que chaque membre de l'équipe peut bien exécuter tout le projet sur son propre PC (ou sur celui de l'IUT). On trouve très facilement en ligne les variantes des lignes de commande de création de projet qui imposent la version à utiliser (Symfony 7.4 et Angular 21 par exemple).

Sommaire

  1. Sur un PC de l'IUT — Configuration rapide (tout est déjà installé)
  2. Sur votre propre PC — Installation complète
  3. Suite commune — Espace de travail, MariaDB, projet Symfony, Adminer

1. Sur un PC de l'IUT

Sur les PC de l'IUT, PHP, Node.js et VSCode sont déjà installés. Il reste cependant à finaliser la configuration de PHP (extensions, php.ini) et à installer Symfony CLI. Nous avons préparé un script qui fait tout cela pour vous.

Procédure

  1. Téléchargez configSAEIUT.zip depuis Moodle.
  2. Décompressez l'archive.
  3. Exécutez configSAEIUT\configPHPIUT.bat.

Ce script va :

  • Copier le bon php.ini (avec les extensions activées) dans le répertoire de PHP.
  • Copier symfony.exe dans le répertoire de PHP (qui est dans le PATH).
  • Exécuter une série de vérifications pour confirmer que tout est en ordre.

⚠️ Ce script doit être exécuté au début de chaque séance (la configuration de PHP est réinitialisée après chaque redémarrage du PC de l'IUT).

Vérifier que tout a fonctionné

Le script affiche les résultats de 3 commandes de test. Vérifiez que vous obtenez bien :

  • php testinstall.php → version PHP 8.4 et toutes les extensions [OK]

  • php composer.phar --version → Composer 2.9

  • symfony version → Symfony CLI 5.16

  • Pour vérifiez l'installation opérationnelle de Symfony : symfony check:requirements.

Si l'une de ces vérifications échoue, ne continuez pas — demandez de l'aide.

Récupérer composer.phar

Le fichier composer.phar se trouve dans le répertoire configSAEIUT\. Vous devrez le copier à la racine de votre espace de travail avant de créer le projet Symfony (cf. Suite commune).

➡️ Passez directement à la Suite commune.

2. Sur votre propre PC

Sur votre PC personnel, il faut installer chaque outil. Les sections suivantes détaillent la procédure pour Windows.

2.1 PHP 8.4

  • Téléchargez et installez PHP 8.4 depuis le site officiel : https://www.php.net/downloads.
    • Le plus simple est de télécharger l'archive ZIP correspondant à votre système.
    • Décompressez le zip et placez le répertoire à un bon endroit pour un logiciel que vous allez utiliser pour plusieurs projets :
      • Pas sur votre bureau, pas non plus dans un répertoire "TP1".
      • Par exemple, sur les PC de l'IUT, PHP a été installé (décompressé) dans C:\Program Files\PHP.
    • Ajoutez le chemin d'accès dans votre PATH.
  • Vérifiez l'installation en ouvrant une invite de commande et en tapant : php -v.
    • Notre version : PHP 8.4.
    • Il est possible que votre ordinateur n'ait pas les DLL MS C++ redistribuables installées.
    • Si c'est le cas, téléchargez-les et installez-les depuis le site officiel de Microsoft.
    • Cf. Google : MS C++ Redistributable.
  • Il faut également personnaliser le fichier de configuration (php.ini) :
    • Il se trouve dans le répertoire de PHP.
    • S'il n'y en a pas, vous pouvez renommer php.ini-development en php.ini.
    • Il faut le modifier pour activer un certain nombre d'extensions.
    • Pour Windows, il suffit de décommenter les lignes suivantes :
    ; À activer dans php.ini
extension_dir = "ext"

extension=curl
extension=fileinfo
extension=intl
extension=mbstring
extension=openssl
extension=sodium      ; calcul de clé de hachage

extension=mysqli      ; MySQLi (connexion MySQL native)
extension=pdo_mysql   ; MySQL avec PDO
extension=pdo_sqlite  ; SQLite avec PDO

2.2 Symfony CLI

  • Installez Symfony :
    • Le plus simple est de télécharger le binaire pour votre PC.
      • Cf. https://symfony.com/download.
      • Il y a une version 386 et une version amd64 (en fonction de votre PC).
      • C'est un zip qui contient l'exécutable symfony.exe.
    • Il suffit de le copier dans le répertoire de PHP (qui est déjà dans le PATH).
    • Mais vous pouvez bien entendu également suivre les instructions sur le site officiel : https://symfony.com/download.
  • Vérifiez l'installation avec la commande : symfony check:requirements.
  • Vérifiez la version avec la commande : symfony version.
    • Notre version : Symfony CLI 5.16.

2.3 Node.js et npm

  • Téléchargez et installez Node.js 22 depuis le site officiel : https://nodejs.org/en/download/.
  • npm est inclus avec Node.js. Vérifiez l'installation avec les commandes :
    node -v
npm -v
    • Nos versions : Node 22 et npm 11.

Compatibilité Angular et Node.js

  • Il est courant que la dernière version de Node.js ne soit pas compatible avec Angular.
    • Cf. https://angular.dev/reference/versions.
  • Pour gérer les versions de Node.js, le plus simple est d'utiliser nvm (Node Version Manager). Il existe une version Windows :
    • https://github.com/coreybutler/nvm-windows/releases.
  • Pour utiliser nvm :
    nvm list            # Liste les versions installées
nvm install 22      # Installe la dernière version 22
nvm use 22          # Utilise la dernière version 22

2.4 Angular CLI (installation locale)

  • Nous n'installons pas Angular CLI globalement. Nous l'utiliserons localement via npx.
  • Pour créer le projet Angular (à l'étape 5), nous utiliserons :
    npx -p @angular/cli@21 ng new front_articles ...
  • Ensuite, depuis le répertoire du projet Angular, les commandes Angular CLI s'exécutent avec :
    npx ng serve
npx ng generate component mon-composant
  • Si vous avez une ancienne version d'Angular CLI installée globalement, nous vous conseillons de la désinstaller pour éviter les conflits :
    npm uninstall -g @angular/cli

2.5 VSCode

  • Installez VSCode (si ce n'est déjà fait).
  • Installez les extensions suivantes :
    • Angular Essentials de John Papa.
    • PHP Intelephense de Ben Mewburn.
    • PHP Namespace Resolver de Mehedi Hassan.
    • Symfony for VSCode de TheNouiller.
    • Twig Language 2.
    • Vérifiez également qu'Emmet est associé aux fichiers Twig (c'est pratique) :
      • Allez dans : Fichier / Préférences / Paramètres / Extensions / Emmet.
      • Dans Include Languages, ajoutez l'élément "twig": "html".

2.6 Vérifier votre installation

Pour valider rapidement votre configuration, téléchargez configSAEIUT.zip depuis Moodle, décompressez-le et exécutez les 3 commandes de test suivantes depuis le répertoire configSAEIUT\ :

php testinstall.php
php composer.phar --version
symfony version

Vous devez obtenir :

  • PHP 8.4 avec toutes les extensions [OK]
  • Composer 2.9
  • Symfony CLI 5.16

Récupérer composer.phar

Le fichier composer.phar se trouve dans le répertoire configSAEIUT\. Vous devrez le copier à la racine de votre espace de travail avant de créer le projet Symfony (cf. section suivante).

3. Suite commune : Espace de travail et projet

Que vous soyez sur un PC de l'IUT ou sur votre propre PC, la suite est identique.

3.1 Espace de travail

  • Créez un répertoire pour notre projet (ex : sae-s6-poc).
  • Lancez VSCode dans ce répertoire.
  • Vous y placerez :
    • composer.phar — copiez-le maintenant depuis configSAEIUT\.
    • Le projet Symfony (créé ci-après).
    • Le projet Angular (créé à l'étape 5).
    • La version portable de MariaDB.
    • Etc. (pour avoir tout sous la main).
  • Vérifiez que composer.phar fonctionne depuis la racine :
    php composer.phar --version
  • Important : par la suite, toutes les commandes composer seront exécutées ainsi :
    # Depuis le répertoire de travail :
php composer.phar require xxx

# Depuis le répertoire du projet Symfony (poc_articles/) :
php ../composer.phar require xxx

3.2 MariaDB

  • Décompressez la version portable de MariaDB (à télécharger sur Moodle).
  • Exécutez start-server.bat pour démarrer le serveur MariaDB.
    • Pas besoin de modifier votre firewall : nous n'avons pas prévu d'accéder à MariaDB depuis une autre machine, seul Symfony l'utilisera en local.
    • Laissez la fenêtre de commande ouverte pendant le fonctionnement du serveur.
    • Tapez Ctrl + C dans cette fenêtre pour couper le serveur (en fin de séance).

3.3 Projet Symfony

  • Créez un nouveau projet Symfony 7.4 avec la commande :
    symfony new poc_articles --version="7.4"
  • Placez-vous dans le répertoire du projet :
    cd poc_articles
  • Installez le bundle Doctrine avec la commande :
    php ../composer.phar require doctrine
    • NB : nous utilisons ../composer.phar car composer.phar est dans le répertoire parent.
    • Lors de l'installation, Symfony Flex vous demandera si vous voulez inclure la configuration Docker : répondez n (non).
  • Ouvrez le fichier .env situé à la racine du projet avec un éditeur de texte.
  • Modifiez la ligne DATABASE_URL pour notre configuration :
    DATABASE_URL="mysql://root:root@127.0.0.1:3306/saepoc?serverVersion=10.8.3-MariaDB&charset=utf8mb4"
    • NB : Avec cette ligne, nous venons de choisir saepoc comme nom de base de données, il ne faudra pas oublier de la créer avec Adminer.
  • Installez HTTPS (si ce n'est déjà fait) :
    symfony server:ca:install
  • Lancez le serveur local Symfony :
    symfony server:start --port=8008
    • Vous pouvez voir la page d'accueil par défaut à l'adresse :
      • https://127.0.0.1:8008/.

3.4 Configuration d'Adminer

  • Décompressez Adminer (à télécharger sur Moodle).
  • Placez le répertoire adminer dans le répertoire public du projet Symfony.
  • Accédez à Adminer via l'URL :
    • https://127.0.0.1:8008/adminer/ dans le navigateur.
    • Utilisateur : root
    • Mot de passe : root
    • C'est le bon moment pour créer la base saepoc.
    • Vous pouvez aussi créer la base en ligne de commande :
      php bin/console doctrine:database:create

3.5 Tester la console du projet Symfony

  • Ouvrez un nouveau terminal ou fermez le serveur Symfony (Ctrl + C).
  • Placez-vous dans le répertoire de Symfony :
    cd poc_articles
  • Testez la connexion à la base de données en exécutant :
    php bin/console doctrine:migrations:migrate
    • Si Doctrine indique qu'il n'y a pas de migration enregistrée : tout est OK, cela confirme que la connexion à la base fonctionne.
    • Sinon, vérifiez :
      • Doctrine installé ?
      • Le driver MySQL activé dans php.ini ?
      • MariaDB est-il lancé ?
      • La base de données saepoc existe-t-elle ?
